# Which MCP requirements apply to Afya?

Reviewed protocol: **2026-07-28**. Core specification source: `modelcontextprotocol/modelcontextprotocol` commit `cf59bb0d8b43e711420f5f7313aa6cca3f1e1898`. Authorization profile: the versioned [OAuth client-credentials extension](https://github.com/modelcontextprotocol/ext-auth/blob/main/specification/stable/oauth-client-credentials/2026-07-28/oauth-client-credentials.mdx). Scope: our three MCP mounts and the API service client, not certification of the borrowed WSO2 server or a general-purpose SDK.

The rule is conditional support, not passing every example. We must implement shared protocol/security rules and every requirement triggered by the features we declare. We do not need to add unrelated product features. Every raw scenario now has an `assessment`, reason and specification references in [application-profile.yaml](application-profile.yaml); raw official failures and untested scenarios stay visible.

## Changes resulting from this review

- Corrected unknown prompt and unknown tool names using a small `MCPServer` subclass overriding public methods. Valid registered calls still delegate to the SDK; no response rewriting, SDK monkey-patching or clinical-feature expansion.
- Removed the known-prompt-error exception from the active report profile. The application gate accepts no protocol failures. There are now 12 supplemental catalogue/argument/error checks across the three mounts.
- Added certificate-verified MCP HTTPS, a separate private-key volume owned by the MCP runtime user, and matching HTTPS resource audiences at the authorization server. The API only mounts the public CA certificate; it never receives the MCP TLS private key. The MCP server still has no OAuth client secret.
- Added baseline service-client checks for OpenID discovery fallback and refusal of mismatched issuer/resource metadata. These complement the real-stack OAuth tests, rather than claiming that browser-flow scenarios have passed.
- Corrected the earlier empty-capability diagnosis: empty prompt/resource lists are explicitly permitted.

## Reading the results honestly

Correcting unknown-tool errors makes two formerly accidental fixture passes fail in the full raw suite: an Unknown tool response is now a JSON-RPC error rather than an `isError` tool execution result. It also reveals two more stateless checks that could not exercise missing reference tools. This is why raw scores can get worse while the actual protocol behavior improves. The four stateless exclusions are named individually; every other assertion and every wire-schema failure remains gated.

These changes support a precise claim about Afya's tested capabilities and service-authentication profile. They do not establish that every requirement of the full SDK-oriented official set has passed, and they do not establish clinical validation or AAIF certification. Conditional features are documented as such; unexercised generic scenarios are not silently converted to passes.
