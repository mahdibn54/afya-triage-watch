# Conformance baseline: afya-mcp on protocol 2025-11-25 (before migration)

Purpose: E13-4 baseline, taken BEFORE any E13 code change, so the migration can be compared with it. This is a
protocol-conformance probe, not a clinical validation and not AAIF certification.

| Item | Value |
|---|---|
| Tool | `@modelcontextprotocol/conformance` 0.1.16 (npm, latest stable; https://github.com/modelcontextprotocol/conformance) |
| Requirement set | server scenarios of the tool, suite `all`, spec versions 2025-06-18 and 2025-11-25 |
| Server under test | `afya_mcp.server:app`, source commit `46866cf` (unchanged `mcp/`), `mcp` SDK 1.30.0, protocol 2025-11-25 |
| Mounts | `/read/mcp`, `/act/mcp`, `/ui/mcp` (each run separately; the three result lists are identical) |
| Auth | the tool cannot send headers, so `scripts/conformance_app.py` adds a throwaway bearer token to each request. Bearer auth itself is covered by the mcp unit tests, not by this run. |

Reproduce (no secrets: the token is a throwaway chosen for the run):

```
cd mcp && pip install -e . && cd ..
AFYA_MCP_TOKEN=throwaway PYTHONPATH=mcp uvicorn conformance_app:app --app-dir scripts --port 9100 &
npx -y @modelcontextprotocol/conformance@0.1.16 server --url http://localhost:9100/read/mcp --suite all -o out
python scripts/conformance_report.py out
```

## How to read the result

The tool's server scenarios are written against its own "everything" reference server (tools such as
`test_simple_text`, prompts, resources, logging, sampling, elicitation). afya-mcp is a three-tool clinical server and
does not implement those fixtures, so most failures mean "feature or fixture not offered by this server", not a
protocol error. They are listed as failures and are NOT presented as passes.

- `tools-call-simple-text` and `tools-call-error` are reported as PASS by the tool, but the tool they call does not
  exist here (the server answered `Unknown tool` with `isError: true`). These two passes are vacuous.
- Real passes that exercise our server: `server-initialize`, `ping`, `tools-list`, `resources-list`, `prompts-list`.
- One genuine finding: `dns-rebinding-protection` fails `localhost-host-valid-accepted` (HTTP 403 for a valid
  localhost Host/Origin). Foreign Host/Origin is correctly rejected (421). Our `TransportSecuritySettings` sets
  `allowed_hosts` but no `allowed_origins`, so any request that carries an Origin header is refused.
- Not implemented by design (read-only clinical tools, no model-side sampling): logging, completion, resource
  subscribe/read fixtures, prompts, sampling, elicitation, progress, image/audio/embedded content, SSE resumability
  (stateless HTTP; priming event and `retry` warned).
